1. Binary Search Pattern Recognition

The key to solving binary search problems efficiently is recognizing when and how to apply them.

When to Use Binary Search

  • The array or search space is sorted (or has monotonic property)
  • You need to find an element or position in O(log n) time
  • The problem asks for minimum/maximum value satisfying a condition
  • You can define a check function that is monotonic (for binary search on answer)

Standard Binary Search

Look for: Sorted array, finding exact element, finding position

Examples: Binary Search (LC 704), Search Insert Position (LC 35)

Complexity: O(log n) O(1)

Finding Bounds (First/Last Occurrence)

Look for: Finding first/last position, counting occurrences, finding insertion point

Examples: Find First and Last Position (LC 34), Search Insert Position (LC 35)

Complexity: O(log n) O(1)

Rotated Sorted Array

Look for: Array was sorted but rotated at some pivot, finding min/max/target

Examples: Search in Rotated Sorted Array (LC 33), Find Minimum (LC 153)

Complexity: O(log n) O(1)

Peak/Valley Finding

Look for: Finding local maximum/minimum, array has peak/valley property

Examples: Find Peak Element (LC 162)

Complexity: O(log n) O(1)

Binary Search on Answer

Look for: Optimization problem (minimize/maximize), monotonic check function, range of possible answers

Examples: Koko Eating Bananas (LC 875), Ship Packages (LC 1011), Split Array (LC 410)

Complexity: O(n * log(range)) O(1)

2. Template Selection Guide

Template 1: Exact Match (left <= right)

Use when: Finding if element exists and returning its index

Loop condition: left <= right

Returns: Index of element or -1

Template 2: Lower Bound (left < right)

Use when: Finding first occurrence or insertion point

Loop condition: left < right

Update: right = mid (when arr[mid] >= target)

Returns: First index where arr[index] >= target

Template 3: Upper Bound (left < right)

Use when: Finding last occurrence

Loop condition: left < right

Update: right = mid (when arr[mid] > target)

Returns: Last index where arr[index] == target

Template 4: Binary Search on Answer

Use when: Finding optimal value in a range

Loop condition: left < right

Update: right = mid (when check(mid) is True)

Returns: Minimum value satisfying check function

3. Problem Decomposition Strategies

For complex binary search problems:

  1. Identify the monotonic property: What property allows binary search?
  2. Define the check function: For binary search on answer, the check function must be monotonic
  3. Determine search boundaries: What are the minimum and maximum possible answers?
  4. Choose the right template: Exact match, lower bound, or binary search on answer?
  5. Handle edge cases: Empty arrays, single elements, all same elements

4. Today's Practice Problems

Problem 1: Search in a 2D Matrix

Search for target in a 2D matrix where each row is sorted and first element of each row > last element of previous row.

Approach: Treat as 1D sorted array, map indices to 2D coordinates.

Complexity: O(log(m*n)) O(1)

Problem 2: Square Root (Integer)

Compute the integer square root of a non-negative integer.

Approach: Binary search on answer, check if mid * mid <= x.

Complexity: O(log x) O(1)

Problem 3: H-Index II

Calculate h-index for sorted citations array.

Approach: Binary search on index, compare citations[i] with n - i.

Complexity: O(log n) O(1)

Problem 4: Smallest Divisor Given Threshold

Find smallest divisor such that sum of ceiling divisions <= threshold.

Approach: Binary search on answer with monotonic check function.

Complexity: O(n * log(max(nums))) O(1)

Problem 5: Find Peak Element (2D Grid)

Find peak element in 2D grid (greater than all adjacent neighbors).

Approach: Binary search on columns, find max row in each column.

Complexity: O(n * log m) O(1)

Problem 6: Median of Two Sorted Arrays

Find median of two sorted arrays of different sizes.

Approach: Binary search on smaller array, partition both arrays.

Complexity: O(log(min(m, n))) O(1)

5. Common Pitfalls and Best Practices

Pitfalls to Avoid:

  • Off-by-one errors: Incorrect loop conditions or boundary updates
  • Infinite loops: When left and right don't converge properly
  • Overflow: mid = (left + right) // 2 can overflow in some languages
  • Wrong template: Using exact match template for finding bounds

Best Practices:

  • Always use: mid = left + (right - left) // 2 to prevent overflow
  • Draw the array: Visualize where target could be
  • Test edge cases: Empty, single element, all same, target at boundaries
  • Practice templates: Memorize all four templates
