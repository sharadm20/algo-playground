Day 16: Binary Search & Advanced Searching

Date: April 14, 2026

Focus: Binary search fundamentals, advanced patterns, and binary search on answer

Overview

Binary search is one of the most fundamental and powerful algorithms in computer science. It allows us to efficiently search for elements in sorted data structures in O(log n) time, and can be extended to solve a wide variety of optimization problems through "binary search on answer".

1. Binary Search Fundamentals

1.1 Prerequisites

  • Sorted Data: The array/collection must be sorted (or have monotonic property)
  • Monotonicity: A property where values consistently increase or decrease
  • Random Access: Ability to access elements by index in O(1) time

1.2 Standard Binary Search

The core idea: repeatedly divide the search space in half.

Algorithm:

  1. Initialize left = 0, right = n - 1
  2. While left <= right:
    • Calculate mid = left + (right - left) // 2
    • If arr[mid] == target, return mid
    • If arr[mid] < target, set left = mid + 1
    • If arr[mid] > target, set right = mid - 1
  3. Return -1 (not found)

1.3 Time Complexity Analysis

Each iteration reduces the search space by half. Starting with n elements:

  • After 1 iteration: n/2 elements
  • After 2 iterations: n/4 elements
  • After k iterations: n/(2^k) elements
  • We stop when n/(2^k) = 1, which gives k = log₂(n)
  • Time Complexity: O(log n)
  • Space Complexity: O(1) iterative, O(log n) recursive

2. Binary Search Templates

Template 1: Finding Exact Match

def binary_search(arr, target): left, right = 0, len(arr) - 1 while left <= right: mid = left + (right - left) // 2 if arr[mid] == target: return mid elif arr[mid] < target: left = mid + 1 else: right = mid - 1 return -1

Template 2: Finding First Occurrence (Lower Bound)

def lower_bound(arr, target): left, right = 0, len(arr) while left < right: mid = left + (right - left) // 2 if arr[mid] < target: left = mid + 1 else: right = mid return left

Template 3: Finding Last Occurrence (Upper Bound)

def upper_bound(arr, target): left, right = 0, len(arr) while left < right: mid = left + (right - left) // 2 if arr[mid] <= target: left = mid + 1 else: right = mid return left - 1

3. Advanced Binary Search Patterns

3.1 Search in Rotated Sorted Array

Problem: Given a sorted array that has been rotated at some pivot, find target.

Example: [4,5,6,7,0,1,2] was originally [0,1,2,4,5,6,7] rotated at index 4.

Approach:

  1. Find which half is properly sorted (left or right of mid)
  2. Check if target lies in the sorted half
  3. If yes, search that half; otherwise, search the other half

Complexity: O(log n) O(1)

3.2 Find Peak Element

Problem: Find an element that is strictly greater than its neighbors.

Approach:

  1. Compare arr[mid] with arr[mid + 1]
  2. If arr[mid] < arr[mid + 1], peak must be on the right
  3. Otherwise, peak is on the left (could be mid itself)

Complexity: O(log n) O(1)

3.3 Find Minimum in Rotated Sorted Array

Problem: Find the minimum element in a rotated sorted array.

Approach:

  1. Compare arr[mid] with arr[right]
  2. If arr[mid] > arr[right], minimum is in right half
  3. Otherwise, minimum is in left half (including mid)

Complexity: O(log n) O(1)

3.4 Single Element in Sorted Array

Problem: Every element appears twice except one. Find the single element.

Example: [1,1,2,3,3,4,4,8,8] → 2

Approach:

  1. Use binary search on indices
  2. Check pairs: before single element, pairs start at even index
  3. After single element, pairs start at odd index

Complexity: O(log n) O(1)

4. Binary Search on Answer

A powerful technique where binary search is applied to the answer space rather than a specific array. Used when:

  • We need to find minimum/maximum value satisfying a condition
  • The condition is monotonic (if x works, all values > x also work, or vice versa)
  • The answer space is a range of integers

4.1 Koko Eating Bananas (LC 875)

Problem: Koko has n piles of bananas, each with piles[i] bananas. She can eat at most k bananas per hour. Find minimum k to eat all bananas within h hours.

Approach:

  1. Binary search on k (eating speed): range [1, max(piles)]
  2. For each k, calculate hours needed: sum(ceil(pile / k) for pile in piles)
  3. If hours <= h, try smaller k (right = mid)
  4. Otherwise, need larger k (left = mid + 1)

Complexity: O(n * log(max_pile)) O(1)

4.2 Capacity to Ship Packages (LC 1011)

Problem: Conveyor belt has packages with weights[i]. Ship within days days. Find minimum ship capacity.

Approach:

  1. Binary search on capacity: range [max(weights), sum(weights)]
  2. For each capacity, simulate shipping and count days needed
  3. If days <= target, try smaller capacity (right = mid)
  4. Otherwise, need larger capacity (left = mid + 1)

Complexity: O(n * log(sum_weights)) O(1)

4.3 Split Array Largest Sum (LC 410)

Problem: Split array into m non-empty subarrays to minimize the largest sum.

Approach:

  1. Binary search on answer: range [max(nums), sum(nums)]
  2. For each possible largest sum, check if we can split into ≤ m subarrays
  3. Greedy check: keep adding to current subarray until adding next would exceed limit

Complexity: O(n * log(sum_nums)) O(1)

5. Key Takeaways

  • Binary search requires sorted data or a monotonic property
  • Time complexity is always O(log n) where n is the search space size
  • Template selection matters: left <= right vs left < right changes behavior
  • Binary search on answer is powerful for optimization problems
  • The check function for binary search on answer must be monotonic
  • Be careful with off-by-one errors in boundary conditions
  • For rotated arrays, always identify which half is sorted first
  • Mid calculation: mid = left + (right - left) // 2 prevents overflow
