Day 11: Dynamic Programming - Part 1

April 9, 2026

Overview

Today we begin Dynamic Programming (DP), one of the most important algorithmic paradigms for solving optimization problems. DP breaks problems into overlapping subproblems and stores their solutions to avoid redundant computation.

Key Properties of DP Problems

  • Optimal Substructure: Optimal solution can be built from optimal solutions of subproblems
  • Overlapping Subproblems: Same subproblems are solved multiple times in naive recursion

When to Use DP

  • Problem asks for maximum/minimum/longest/shortest/optimal value
  • Problem involves making a sequence of decisions
  • Recursive solution has overlapping subproblems
  • Solutions to smaller instances help solve larger instances

Two Approaches to Dynamic Programming

Top-Down Approach (Memoization)

Start with the original problem and recursively break it into subproblems. Store results in a cache to avoid recomputing.

Advantages: Natural, only computes needed subproblems, easier to implement

Disadvantages: Recursion overhead, may cause stack overflow, uses call stack space

Bottom-Up Approach (Tabulation)

Start with smallest subproblems and iteratively build up. Fill a table systematically.

Advantages: No recursion overhead, better space efficiency, no stack overflow risk

Disadvantages: May compute unnecessary subproblems, requires careful ordering

Classic 1D DP Problems

1. Fibonacci Sequence

Recurrence: F(n) = F(n-1) + F(n-2), F(0) = 0, F(1) = 1
def fibonacci_optimized(n): if n <= 1: return n prev2, prev1 = 0, 1 for _ in range(2, n + 1): curr = prev1 + prev2 prev2, prev1 = prev1, curr return prev1

Time: O(n), Space: O(1)

2. Climbing Stairs

Identical to Fibonacci! Ways(n) = Ways(n-1) + Ways(n-2)

Base cases: Ways(0) = 1, Ways(1) = 1

3. House Robber

Recurrence: dp[i] = max(dp[i-1], dp[i-2] + nums[i])

At each house: either skip it (take dp[i-1]) or rob it (take dp[i-2] + current)

4. Coin Change

Recurrence: dp[i] = min(dp[i], dp[i - coin] + 1) for each coin

Base case: dp[0] = 0, Initialize with infinity for impossible values

Knapsack Problems

0/1 Knapsack

Each item can only be taken once (0 or 1)

dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])

Time: O(n × W), Space: O(W) with optimization

Unbounded Knapsack

Can take unlimited copies of each item

dp[w] = max(dp[w], dp[w-weight[i]] + value[i])

Key difference: Iterate forwards (can reuse items) vs backwards in 0/1 knapsack

Target Sum

Convert to subset sum: find subset with sum = (sum(nums) + target) / 2

String Dynamic Programming

Longest Common Subsequence (LCS)

If s1[i] == s2[j]: dp[i][j] = 1 + dp[i-1][j-1]
Else: dp[i][j] = max(dp[i-1][j], dp[i][j-1])

Time: O(m × n), Space: O(m × n)

Edit Distance (Levenshtein Distance)

If word1[i] == word2[j]: dp[i][j] = dp[i-1][j-1]
Else: dp[i][j] = 1 + min(delete, insert, replace)

Base cases: dp[i][0] = i, dp[0][j] = j

Longest Palindromic Subsequence

Approach 1: Reverse string and find LCS with original

If s[i] == s[j]: dp[i][j] = 2 + dp[i+1][j-1]
Else: dp[i][j] = max(dp[i+1][j], dp[i][j-1])

DP Problem-Solving Strategy

  1. Define the State: What does dp[i] or dp[i][j] represent?
  2. Find the Recurrence Relation: How to express current state in terms of previous states?
  3. Identify Base Cases: What are the simplest solvable cases?
  4. Determine Computation Order: What order to fill the DP table?
  5. Space Optimization (Optional): Can you reduce space complexity?
