## Overview

The 30-day DSA study plan has covered the most important algorithmic patterns used in technical interviews. Today you'll step back and see the big picture — a strategic review of patterns and when to apply them. Recognizing the underlying pattern in a problem is often harder than implementing the solution.

<InsightBox title="The One-Sentence Rule">
Every problem in an interview maps to one of these patterns. Practice pattern recognition by asking: "What is this problem really asking?" before you write any code.
</InsightBox>

## Decision Flowchart

<InsightBox title="Pattern Selection Guide">
**Is the input sorted or nearly sorted?**
- Yes → **Binary Search** or **Two Pointers**
- No → Continue

**Are you looking for a subarray/substring with a property?**
- Yes → **Sliding Window**

**Is it a graph or tree problem?**
- Need shortest path? → **BFS / Dijkstra**
- Need connectivity? → **Union Find**
- Need dependency order? → **Topological Sort**
- Need minimum connections? → **MST**

**Does the problem ask for min/max or count of ways?**
- Yes → **Dynamic Programming** (if optimal substructure)

**Small input and need all combinations?**
- Yes → **Backtracking**

**Can you make a locally optimal choice that seems globally optimal?**
- Yes → **Greedy**
</InsightBox>

## Key Takeaways

<InsightBox title="Strategic Review">
- Pattern recognition is a skill you build through practice — the more problems you solve, the faster you identify patterns.
- Most medium-difficulty problems combine two patterns (e.g., BFS on a graph built with Union Find).
- Always analyze complexity: time vs. space trade-off is a common interview discussion point.
- Review this table before every mock interview. Over time, pattern matching becomes automatic.
</InsightBox>
