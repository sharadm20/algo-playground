## Overview

A **segment tree** is a binary tree that stores intervals (segments) and supports two operations efficiently: range queries (sum, min, max over a subarray) and point updates (modify one element). Both operations run in O(log n) time, making segment trees vastly superior to naive O(n) per-query approaches when dealing with dynamic arrays.

The tree is stored in a flat array indexed like a heap: the root at index 1, left child at `2*i`, right child at `2*i+1`. Each node stores the aggregate value (sum, min, max) for its segment. Building takes O(n), and queries/updates each take O(log n). **Lazy propagation** extends this to range updates (add a value to every element in a range) while maintaining O(log n) per operation.

## Key Concepts

- **Segment Tree Structure**: A full binary tree over the array. Leaf nodes store individual elements; internal nodes store aggregated values of their children.
- **Range Query**: Recursively traverse the tree. If a node's segment is fully within the query range, return its value. If partially overlapping, query both children and combine.
- **Point Update**: Update a leaf, then recalculate its ancestors up to the root — O(log n) nodes touched.
- **Lazy Propagation**: Defer range updates. A "lazy" value at an ancestor means all nodes below still need the update. Propagate only when you actually visit a child.

## Code Example

<CodePlayground language="python" initialCode={`class SegmentTree:
    def __init__(self, data: list[int]):
        n = len(data)
        self.tree = [0] * (4 * n)
        self.n = n
        self._build(data, 1, 0, n - 1)

    def _build(self, data: list[int], node: int, l: int, r: int) -> None:
        if l == r:
            self.tree[node] = data[l]
            return
        mid = (l + r) // 2
        self._build(data, node * 2, l, mid)
        self._build(data, node * 2 + 1, mid + 1, r)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]

    def query(self, ql: int, qr: int) -> int:
        return self._query(1, 0, self.n - 1, ql, qr)

    def _query(self, node: int, l: int, r: int, ql: int, qr: int) -> int:
        if ql <= l and r <= qr:
            return self.tree[node]
        mid = (l + r) // 2
        res = 0
        if ql <= mid:
            res += self._query(node * 2, l, mid, ql, qr)
        if qr > mid:
            res += self._query(node * 2 + 1, mid + 1, r, ql, qr)
        return res

    def update(self, idx: int, val: int) -> None:
        self._update(1, 0, self.n - 1, idx, val)

    def _update(self, node: int, l: int, r: int, idx: int, val: int) -> None:
        if l == r:
            self.tree[node] = val
            return
        mid = (l + r) // 2
        if idx <= mid:
            self._update(node * 2, l, mid, idx, val)
        else:
            self._update(node * 2 + 1, mid + 1, r, idx, val)
        self.tree[node] = self.tree[node * 2] + self.tree[node * 2 + 1]


st = SegmentTree([1, 3, 5, 7, 9, 11])
print(st.query(1, 3))  # 15 (3+5+7)
st.update(1, 10)
print(st.query(1, 3))  # 22 (10+5+7)
`} />

## Key Takeaways

<InsightBox title="Key Insights">
- Segment trees require 4× the array size for safe storage — a common pitfall is allocating only 2×.
- The query and update methods have almost identical structure; learn one and the other follows.
- Lazy propagation doubles the code complexity but transforms range updates from O(n log n) to O(log n).
- For prefix-sum queries only, a Fenwick tree (Day 19) is simpler and faster. Use segment trees when you need range queries (not just prefix) or range updates.
</InsightBox>
