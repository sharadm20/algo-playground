## Overview

Three foundational advanced data structures appear in this session. A **Fenwick Tree (BIT)** is a simpler, faster alternative to segment trees for prefix operations. **Disjoint Set Union (Union-Find)** tracks connected components under union operations with near-constant amortized time. **LRU Cache** is an elegant combination of hash map and doubly-linked list that's a staple of system design interviews.

Each structure solves a distinct problem: BIT for dynamic prefix sums, Union-Find for graph connectivity, and LRU Cache for bounded-memory caching with access-order eviction. Together they round out the essential advanced toolkit.

## Key Concepts

- **Fenwick Tree (BIT)**: Uses 1-indexed array where `bit[i]` stores the sum of a range of length `i & -i` ending at i. Point update and prefix sum both run in O(log n). Simpler code than segment trees, but only supports prefix operations natively.
- **Union-Find**: Tracks parent pointers and component sizes. Path compression (flatten the tree during find) and union by size/rank give nearly O(1) amortized operations.
- **LRU Cache**: A hash map from keys to doubly-linked list nodes. On every access, move the node to the head. On eviction, remove from the tail. All operations in O(1).

<CodePlayground language="python" initialCode={`class FenwickTree:
    def __init__(self, n: int):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx: int, delta: int) -> None:
        i = idx + 1
        while i <= self.n:
            self.bit[i] += delta
            i += i & -i

    def prefix_sum(self, idx: int) -> int:
        i = idx + 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s


class UnionFind:
    def __init__(self, n: int):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x: int) -> int:
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x: int, y: int) -> bool:
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False
        if self.rank[rx] < self.rank[ry]:
            self.parent[rx] = ry
        elif self.rank[rx] > self.rank[ry]:
            self.parent[ry] = rx
        else:
            self.parent[ry] = rx
            self.rank[rx] += 1
        return True


ft = FenwickTree(5)
for i, v in enumerate([1, 2, 3, 4, 5]):
    ft.add(i, v)
print(ft.prefix_sum(3))  # 10
`} />

<CodePlayground language="javascript" initialCode={`// LRU Cache in JavaScript
class LRUCache {
  constructor(capacity) {
    this.cap = capacity;
    this.cache = new Map();
  }

  get(key) {
    if (!this.cache.has(key)) return -1;
    const val = this.cache.get(key);
    this.cache.delete(key);
    this.cache.set(key, val);
    return val;
  }

  put(key, value) {
    if (this.cache.has(key)) this.cache.delete(key);
    else if (this.cache.size >= this.cap) {
      const oldest = this.cache.keys().next().value;
      this.cache.delete(oldest);
    }
    this.cache.set(key, value);
  }
}

const lru = new LRUCache(2);
lru.put(1, 1);
lru.put(2, 2);
console.log(lru.get(1));  // 1
lru.put(3, 3);
console.log(lru.get(2));  // -1 (evicted)
`} />

## Key Takeaways

<InsightBox title="Key Insights">
- Fenwick trees are less flexible than segment trees but use half the memory and have simpler code. Use them when you only need prefix sums or prefix min/max.
- Union-Find with path compression + union by rank achieves nearly O(α(n)) amortized — effectively constant. It's the go-to for dynamic connectivity problems.
- The Map-based LRU (JavaScript/Java) and OrderedDict-based LRU (Python) both exploit ordered key storage. The hand-rolled doubly-linked-list version tests implementation skill.
- All three structures appear in production code regularly. Understanding their tradeoffs is part of systems-level thinking.
</InsightBox>
