## Overview

Week 2 focused on graphs — from basic BFS/DFS traversal through Dijkstra's shortest path and topological sorting. Today's review cements these concepts with mixed problems that may combine graph thinking with earlier techniques like hash maps and stacks.

The key insight for graph problems is recognizing when a problem *is* a graph problem even when it doesn't look like one. Course prerequisites? That's a directed graph. Computer network latency? Weighted graph. Social connections? Undirected graph. Once you map the problem onto the right graph representation, the algorithm follows naturally.

## Multi-Language: Dijkstra in Three Flavours

<CodePlayground language="python" initialCode={`# Python — heapq makes it concise
import heapq
def dijkstra(graph, start):
    dist = {node: float('inf') for node in graph}
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(pq, (d + w, v))
    return dist
`} />

<CodePlayground language="javascript" initialCode={`// JavaScript — manual priority queue with array
function dijkstra(graph, start) {
    const dist = {};
    for (const node in graph) dist[node] = Infinity;
    dist[start] = 0;
    const pq = [[0, start]];
    while (pq.length) {
        pq.sort((a, b) => a[0] - b[0]);
        const [d, u] = pq.shift();
        if (d > dist[u]) continue;
        for (const [v, w] of graph[u]) {
            if (d + w < dist[v]) {
                dist[v] = d + w;
                pq.push([d + w, v]);
            }
        }
    }
    return dist;
}
`} />

## Practice Problems

<ProblemCard title="Pacific Atlantic Water Flow" difficulty="medium" pattern="DFS / BFS from Borders">
  Given an `m × n` matrix of heights, water can flow from a cell to neighbors of equal or lower height. Return all cells where water can flow to both the Pacific (top/left edges) and Atlantic (bottom/right edges) oceans.

  **Example:** `heights = [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]]` → `[[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]`
</ProblemCard>

<ProblemCard title="Word Ladder" difficulty="hard" pattern="BFS Shortest Path in Graph">
  Given `beginWord`, `endWord`, and a `wordList`, each transformation changes exactly one letter. Return the length of the shortest transformation sequence from `beginWord` to `endWord`. Return `0` if no such sequence exists.

  **Example:** `beginWord = "hit"`, `endWord = "cog"`, `wordList = ["hot","dot","dog","lot","log","cog"]` → `5` (hit→hot→dot→dog→cog)
</ProblemCard>

<ProblemCard title="Alien Dictionary" difficulty="hard" pattern="Topological Sort">

## Key Takeaways

<InsightBox title="Key Insights">
- The hardest part of graph problems is recognizing they are graph problems. Train yourself to see vertices and edges in any data.
- BFS is your default for unweighted shortest path; Dijkstra for weighted.
- Topological sort works on DAGs only — if you detect fewer nodes output than input, there's a cycle.
- Review weeks are for identifying weak spots. If any problem felt hard, revisit that day's content before moving on.
</InsightBox>
