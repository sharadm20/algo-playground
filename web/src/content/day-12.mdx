## Overview

While Day 11 covered linear DP, many real problems live in higher dimensions. **2D DP** is the natural extension: instead of a 1D array, we use a 2D grid where each cell `dp[i][j]` represents the solution to a subproblem defined by two parameters. The classic examples are grid path problems (counting or minimizing paths through a matrix) and the knapsack family (choosing items under a weight constraint).

The 2D DP pattern is recognisable by two independent dimensions of state — usually indices into two sequences, or a position and a remaining budget. As you work through these problems, pay attention to how the recurrence references neighboring cells in the table.

## Key Concepts

- **Grid DP**: Walking through a matrix, usually moving right/down. The value at `dp[i][j]` depends on `dp[i-1][j]` and `dp[i][j-1]`.
- **Knapsack Pattern**: For each item, decide whether to take it or skip it. The state is `dp[i][w]` = best value using first `i` items with capacity `w`.
- **Space Reduction**: Many 2D DP problems only need the previous row (or previous column), letting you compress `O(n*m)` space to `O(min(n,m))`.
- **Initialization**: The base cases along row 0 and column 0 are often trivial (e.g., only one way to move along edges) — don't forget them.

    dp = [[1] * n for _ in range(m)]
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i - 1][j] + dp[i][j - 1]
    return dp[m - 1][n - 1]


def coin_change(coins: list[int], amount: int) -> int:
    dp = [amount + 1] * (amount + 1)
    dp[0] = 0
    for a in range(1, amount + 1):
        for c in coins:
            if a - c >= 0:
                dp[a] = min(dp[a], 1 + dp[a - c])
    return dp[amount] if dp[amount] != amount + 1 else -1


print(unique_paths(3, 7))  # 28
print(coin_change([1, 2, 5], 11))  # 3

## Key Takeaways

<InsightBox title="Key Insights">
- 2D DP problems have a natural table: the two axes are the two dimensions of state. Draw the table when stuck.
- For unbounded knapsack (unlimited copies of each item), iterate amount-outer / coin-inner. For 0/1 knapsack (at most one copy), iterate coin-outer / amount-inner.
- Space optimization is almost always possible: if the recurrence only looks at the current and previous row, use two arrays instead of a full matrix.
- When the answer is the minimum or maximum of several possibilities, a sentinel value (like `amount + 1` or `inf`) for unreachable states keeps the recurrence clean.
</InsightBox>
