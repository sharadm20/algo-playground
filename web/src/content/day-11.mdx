## Overview

Dynamic Programming is a technique for solving problems by breaking them into overlapping subproblems and storing their results to avoid redundant computation. It's one of the most powerful — and most feared — paradigms in algorithm design. The core insight is that many problems that seem to require exponential time can be solved in polynomial time once you identify the right subproblem decomposition.

There are two main approaches to DP: **memoization** (top-down, recursive with caching) and **tabulation** (bottom-up, iterative with a table). Both exploit the same underlying recurrence; the choice is largely about style and space constraints. The Fibonacci sequence is the canonical example that illustrates both approaches.

## Key Concepts

- **Overlapping Subproblems**: The problem can be broken into subproblems that are reused multiple times. If subproblems don't overlap, you're using divide-and-conquer, not DP.
- **Optimal Substructure**: An optimal solution to the problem can be constructed from optimal solutions to its subproblems. This property lets you build answers incrementally.
- **Memoization (Top-Down)**: Start with the original problem and recurse down, caching results of subproblems as you compute them. Intuitive but risks stack overflow on deep recursion.
- **Tabulation (Bottom-Up)**: Start from the smallest subproblems and build up iteratively. Usually more efficient in practice and avoids recursion overhead.

<CodePlayground language="python" initialCode={`def fib_memo(n: int, memo: list[int] | None = None) -> int:
    if n <= 1:
        return n
    if memo is None:
        memo = [-1] * (n + 1)
    if memo[n] != -1:
        return memo[n]
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]


def fib_tab(n: int) -> int:
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]


print(fib_memo(10), fib_tab(10))  # 55 55

## Key Takeaways

<InsightBox title="Key Insights">
- DP is applicable when a problem has both overlapping subproblems and optimal substructure — verify both properties before reaching for DP.
- Start with a brute-force recursive solution, then add memoization. Only convert to tabulation if you need better space or want to avoid recursion overhead.
- The recurrence is the heart of any DP solution. Write it clearly on paper before coding.
- Space optimization is often possible: if dp[i] only depends on dp[i-1] and dp[i-2], you don't need the full array.
</InsightBox>
