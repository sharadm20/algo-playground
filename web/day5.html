Day 5: Linked List

Singly/Doubly Linked Lists, Fast-Slow Pointers, Reversal, Cycle Detection

Current 📅 April 3, 2026 ⏱️ 4-5 hours

Topic Overview

Day 5 introduces linked lists, a fundamental linear data structure where elements are connected through pointers/references. Unlike arrays, linked lists provide efficient insertions and deletions but sacrifice random access. Mastering linked list manipulation is crucial for technical interviews and understanding more complex data structures like trees and graphs.

Why Linked Lists Matter:

  • Foundation for trees, graphs, and hash tables with chaining
  • Dynamic size - no need to pre-allocate memory
  • Efficient insertions/deletions (O(1) with pointer)
  • Essential for implementing LRU caches, memory management
  • Tests pointer manipulation skills in interviews

Core Concepts

1. Singly Linked List

Each node contains data and a pointer to the next node. The list is accessed through a head pointer. Traversal is only possible in one direction (head to tail). 

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

Operations:

  • Append (end): O(n) - traverse to tail, or O(1) with tail pointer
  • Prepend (beginning): O(1) - update head pointer
  • Delete: O(n) - find node, update previous node's pointer
  • Search: O(n) - linear traversal required
  • Access by index: O(n) - no random access

2. Doubly Linked List

Each node contains data, a pointer to the next node, and a pointer to the previous node. Allows bidirectional traversal but uses more memory. 

class DoublyListNode:
    def __init__(self, val=0, prev=None, next=None):
        self.val = val
        self.prev = prev
        self.next = next

Advantages over Singly Linked List:

  • Bidirectional traversal (forward and backward)
  • O(1) deletion if node pointer is given (need prev pointer)
  • Easier to implement operations like reverse traversal

Disadvantages:

  • More memory per node (extra pointer)
  • More complex operations (must update both prev and next)

Key Patterns & Techniques

Pattern 1: Fast-Slow Pointers (Tortoise and Hare)

Concept: Use two pointers moving at different speeds. Fast pointer moves 2 steps while slow moves 1 step. This pattern is incredibly powerful for various linked list problems.

Applications:

  • Find middle element: When fast reaches end, slow is at middle
  • Detect cycle: If fast and slow meet, there's a cycle
  • Find cycle start: Reset one pointer to head, move both at same speed
  • Find kth from end: Move first pointer k steps ahead, then move both

Time Complexity: O(n) - each pointer traverses the list at most once

Space Complexity: O(1) - only uses two pointers, no extra space

Pattern 2: Linked List Reversal

Concept: Reverse the direction of all links using three pointers: prev, curr, and next_temp. This is one of the most fundamental linked list operations. 

def reverse_linked_list(head):
    prev = None
    curr = head
    
    while curr:
        next_temp = curr.next  # Save next node
        curr.next = prev       # Reverse link
        prev = curr            # Move prev forward
        curr = next_temp       # Move curr forward
    
    return prev  # New head

Time Complexity: O(n) - visit each node once

Space Complexity: O(1) iterative, O(n) recursive (call stack)

Pattern 3: Merge Sorted Lists

Concept: Use a dummy node and merge by comparing values. This pattern is essential for divide-and-conquer algorithms and external sorting.

Algorithm:

  1. Create dummy node to simplify edge cases
  2. Compare heads of both lists, attach smaller to result
  3. Move pointer of attached list forward
  4. Repeat until one list is exhausted
  5. Attach remaining nodes from non-empty list

Time Complexity: O(n + m) where n and m are lengths of both lists

Space Complexity: O(1) - only uses pointers, modifies in-place

Pattern 4: Cycle Detection

Floyd's Cycle Detection Algorithm: Also known as the "Tortoise and Hare" algorithm. Uses two pointers moving at different speeds to detect if a linked list has a cycle.

Algorithm:

  1. Initialize slow and fast pointers to head
  2. Move slow one step, fast two steps
  3. If fast reaches null, no cycle exists
  4. If slow and fast meet, cycle exists
  5. To find cycle start: reset slow to head, move both one step at a time until they meet

Why They Meet: In a cycle of length k, the distance between slow and fast decreases by 1 each step. They must meet within k steps.

Additional Patterns

Remove Nth Node From End

Technique: Use two pointers with a gap of n nodes. When first reaches end, second is at nth from end.

Palindrome Check

Technique: Find middle, reverse second half, compare with first half. Can restore list afterward if needed.

Intersection of Two Lists

Technique: Traverse both lists, switch heads when reaching end. They meet at intersection point or both reach null. This works because both pointers travel the same total distance.

Reorder List

Technique: Find middle, reverse second half, merge alternately. Combines multiple patterns into one solution.

Tips & Best Practices

  • Always handle edge cases: empty list, single node, two nodes
  • Use dummy nodes to simplify edge case handling
  • Draw diagrams to visualize pointer movements
  • Be careful with pointer order - update in correct sequence
  • Test with cycles by manually creating them in code
  • For fast-slow pointers, always check fast and fast.next
  • When reversing, save next node before updating pointers
  • Use type hints for cleaner, more maintainable code
