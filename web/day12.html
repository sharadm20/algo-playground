1. DP on Trees

Key Characteristics

  • Problems exhibit optimal substructure on tree structures
  • Solution for a node depends on solutions for its children
  • Often solved using post-order traversal (process children before parent)
  • State typically includes the current node and possibly additional information

1.1 Tree Diameter

Problem: Find the longest path between any two nodes in a tree.

DP State:
- height[u] = 1 + max(height[v] for all children v)
- diameter[u] = max(diameter in subtrees, path through u with two deepest branches)
# Python: Tree Diameter def tree_diameter(tree): n = len(tree) diameter = [0] def dfs(node, parent=-1): max_height1 = max_height2 = 0 for child in tree[node]: if child != parent: height = dfs(child, node) if height > max_height1: max_height2 = max_height1 max_height1 = height elif height > max_height2: max_height2 = height diameter[0] = max(diameter[0], max_height1 + max_height2) return max_height1 + 1 dfs(0) return diameter[0]

1.2 Maximum Independent Set on Trees

Problem: Find maximum size subset of nodes such that no two nodes are adjacent.

DP State:
- dp[u][0] = max independent set when u is NOT included
- dp[u][1] = max independent set when u IS included

Transitions:
- dp[u][0] = sum(max(dp[v][0], dp[v][1]) for all children v)
- dp[u][1] = 1 + sum(dp[v][0] for all children v)

2. Bitmask DP

When to Use Bitmask DP

  • Problem involves subsets of a small set (typically n ≤ 20)
  • Need to track which elements have been used/selected
  • State space can be represented as 2^n possibilities

3. Digit DP

Key Technique

  • Process digits from left to right
  • Track whether we're still "tight" (bounded by the original number)
  • Use memoization for overlapping subproblems
  • Common state: (position, tight_constraint, started, additional_states...)

3.1 Count Numbers Without Digit 4

Problem: Count numbers from 0 to N that don't contain digit 4.

DP State: dp(pos, tight, started)
- pos: Current digit position (from left)
- tight: Whether we're still bounded by N
- started: Whether we've started placing non-zero digits

Transition:
limit = digits[pos] if tight else 9
for digit in 0..limit+1:
  if digit == 4: continue
  new_tight = tight and (digit == limit)
  count += dp(pos+1, new_tight, started or digit > 0)
# Python: Digit DP def count_without_digit_4(n): digits = [int(d) for d in str(n)] memo = {} def dp(pos, tight, started): if pos == len(digits): return 1 if started else 0 state = (pos, tight, started) if state in memo: return memo[state] limit = digits[pos] if tight else 9 count = 0 for digit in range(limit + 1): if digit == 4: continue new_tight = tight and (digit == limit) new_started = started or (digit > 0) count += dp(pos + 1, new_tight, new_started) memo[state] = count return count return dp(0, True, False) + 1 # +1 for number 0

4. Matrix Chain Multiplication

Problem Statement

Given matrices A₁, A₂, ..., Aₙ where matrix Aᵢ has dimensions p[i-1] × p[i], find the minimum number of scalar multiplications needed to compute the product.

Key Insight: Matrix multiplication is associative but not all parenthesizations are equal in cost.

DP State: dp[i][j] = minimum multiplications to compute A[i..j]

Base Case: dp[i][i] = 0

Transition:
dp[i][j] = min(dp[i][k] + dp[k+1][j] + p[i-1]*p[k]*p[j]) for k in range(i, j)

Complexity: O(n³) time, O(n²) space
# Python: Matrix Chain Multiplication def matrix_chain_order(dimensions): n = len(dimensions) - 1 # Number of matrices dp = [[0] * n for _ in range(n)] for l in range(2, n + 1): # chain length for i in range(n - l + 1): j = i + l - 1 dp[i][j] = float('inf') for k in range(i, j): cost = (dp[i][k] + dp[k + 1][j] + dimensions[i] * dimensions[k + 1] * dimensions[j + 1]) dp[i][j] = min(dp[i][j], cost) return dp[0][n - 1]

4.1 Boolean Parenthesization

Problem: Count ways to parenthesize boolean expression to evaluate to True.

DP States:
- dpT[i][j] = ways to get True from symbols[i..j]
- dpF[i][j] = ways to get False from symbols[i..j]

Transitions: Based on operator at position k
- AND: dpT += dpT[i][k] * dpT[k+1][j]
- OR: dpT += total_left * total_right - dpF[i][k] * dpF[k+1][j]
- XOR: dpT += dpT[i][k] * dpF[k+1][j] + dpF[i][k] * dpT[k+1][j]

5. DP Optimization Techniques

Space Optimization

Observe that only previous row/column is needed. Use rolling arrays or track only necessary previous values.

Example: Fibonacci from O(n) space to O(1) space

State Compression

When DP state has redundant information, compress it using bitmasks or mathematical properties.

Example: House Robber II - circular constraint

Knuth's Optimization

For cost functions satisfying quadrangle inequality and monotonicity, optimize O(n³) to O(n²).

Application: Optimal BST, certain MCM variants

Divide & Conquer Opt.

When opt[i][j-1] ≤ opt[i][j] ≤ opt[i][j+1], use divide and conquer to reduce complexity.

Complexity: O(n² log n) or better

Convex Hull Trick

For DP with transitions involving linear/quadratic functions, find minimum over many linear functions.

Complexity: O(n²) → O(n log n)

Technique When to Use Complexity Constraints

Common Pitfalls & Tips

⚠️ Common Pitfalls

  • Not considering all possible transitions
  • Wrong base cases leading to incorrect results
  • Space inefficiency causing Memory Limit Exceeded
  • Not recognizing when optimization techniques apply
  • Off-by-one errors in digit DP bounds
  • Forgetting to handle edge cases (empty input, single element)

✅ Tips for Mastery

  • Practice identifying DP patterns quickly
  • Always verify with small test cases
  • Learn to recognize when optimizations apply
  • Understand both recursive and iterative implementations
  • Practice bit manipulation for bitmask DP
  • Draw DP tables for small inputs to understand transitions

Problem-Solving Strategy

  1. Identify the structure: Tree, sequence, subset, digits?
  2. Define the state: What information do we need to track?
  3. Find transitions: How do we build larger solutions from smaller ones?
  4. Check constraints: Can we optimize space/time?
  5. Verify base cases: What are the simplest subproblems?
  6. Implement carefully: Watch for off-by-one errors and state transitions
